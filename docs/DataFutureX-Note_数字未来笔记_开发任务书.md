**中文名称：** 数字未来笔记

**产品形态：** 本地优先的桌面 Markdown 笔记软件

---

## 1. 项目概述

### 1.1 产品定位

DataFutureX-Note 是一款面向个人知识整理、技术文档管理和日常记录的 Windows 桌面笔记软件。软件以本地文件系统为核心，使用真实文件夹组织分类，使用标准 Markdown（`.md`）文件保存笔记内容。

### 1.2 建设目标

1. 首次启动时引导用户指定 PC 本机笔记库根目录。
2. 提供目录、章节、内容三栏式笔记管理界面。
3. 支持文件夹和 Markdown 笔记的新增、删除、修改、查询。
4. 支持 Markdown 编辑、预览和自动保存。
5. 支持按修改时间和文件名称排序。
6. 支持整个笔记库或任意层级文件夹打包备份、导入恢复。
7. 支持将笔记导出为 Word（DOCX）和 PDF。
8. 支持浅色、深色、跟随系统三种主题。
9. 核心功能离线可用，不依赖云端服务或远程数据库。

### 1.3 产品原则

- **本地优先：** 笔记正文保存在用户指定的本地目录。
- **开放格式：** Markdown 文件可由其他编辑器直接打开。
- **目录即分类：** 文件夹结构直接映射到界面目录树。
- **数据可迁移：** 支持 ZIP 备份和恢复，不形成私有格式锁定。
- **安全可控：** 文件操作限定在用户授权的笔记库根目录内。
- **轻量易用：** V1.0 不引入账号体系、云同步、服务端或数据库。

## 3. 技术方案

### 3.1 推荐技术栈

| 层次 | 技术 | 用途 |
|---|---|---|
| 桌面容器 | Electron | Windows 桌面运行、系统能力 |
| 前端框架 | Vue 3 + TypeScript | 页面和交互 |
| 构建工具 | Vite | 开发和构建 |
| UI 组件 | Element Plus（或轻量自定义组件） | 基础控件 |
| 状态管理 | Pinia | 界面状态 |
| Markdown 编辑器 | CodeMirror 6 | 源码编辑、语法高亮 |
| Markdown 解析 | markdown-it | 预览和 HTML 转换 |
| 文件系统 | Node.js fs/promises | 本地文件读写 |
| ZIP | adm-zip、yazl/yauzl 或同类维护良好的库 | 备份和导入 |
| Word | docx（docx.js） | 生成 DOCX |
| PDF | Electron webContents.printToPDF | HTML 页面转 PDF |
| 主题 | CSS Variables + Pinia + Electron nativeTheme | 主题管理 |
| 打包 | electron-builder | Windows 安装包 |

### 3.2 架构原则

- Vue 渲染进程不直接访问 Node.js 文件系统。
- 文件系统、备份、导入和导出等受控操作由 Electron 主进程执行。
- 通过 Preload 暴露白名单 API，使用 IPC 通信。
- Markdown 文件是笔记正文的唯一事实来源。
- 不使用数据库保存重复的笔记正文；必要时可在后续版本引入可重建索引。
- 应用配置、临时恢复数据和日志放在 Electron 用户数据目录，不与笔记正文混放。

### 3.3 逻辑架构

```text
DataFutureX-Note
├── Vue 3 Renderer
│   ├── 三栏主界面
│   ├── FolderTree / NoteList
│   ├── MarkdownEditor / MarkdownPreview
│   ├── ExportDialog / ThemeSwitcher
│   └── Settings
│
├── Preload（受控 API）
│
├── Electron Main
│   ├── FolderService
│   ├── NoteService
│   ├── FileSystemService
│   ├── SearchService
│   ├── BackupService / ImportService
│   ├── WordExportService / PdfExportService
│   ├── ThemeService / SettingsService
│   └── RecoveryService
│
└── PC 本地文件系统
    ├── 用户指定的笔记库根目录
    └── Electron userData（配置、日志、临时恢复数据）
```

## 4. 初始化与本地笔记库

### 4.1 首次启动

1. 启动应用并检查初始化配置。
2. 若没有有效根目录配置，显示欢迎页和初始化向导。
3. 用户通过系统目录选择对话框选择本地文件夹。
4. 检查目录是否存在、是否可读写、是否为有效目录。
5. 用户确认后保存根目录配置。
6. 扫描根目录，建立文件夹树和笔记列表。
7. 若目录为空，允许直接创建第一个分类或笔记。

### 4.2 根目录规则

- 根目录由用户明确指定。
- 根目录本身显示为目录树顶层节点。
- 根目录不可通过软件删除或重命名。
- 允许用户选择已有目录作为笔记库。
- 不得自动清空或格式化用户选定目录。
- 修改根目录时必须明确区分“切换到已有笔记库”和“创建/选择新笔记库”。
- 切换前检查未保存内容；原目录数据保持不变。
- 应用只能操作根目录范围内的文件，以及用户通过明确文件选择操作授权的导入/导出目标。

### 4.3 本地目录结构

```text
D:/DataFutureX/Notes/
├── 技术文档/
│   ├── Java/
│   │   ├── SpringBoot基础.md
│   │   └── SpringAI架构.md
│   └── AI/
│       ├── RAG知识库.md
│       └── Agent设计.md
├── 工作记录/
│   └── 项目会议记录.md
├── 学习笔记/
│   └── 技术学习.md
└── 日常记录/
    └── 生活记录.md
```

规则：

- 文件夹对应分类。
- `.md` 文件对应单篇笔记。
- 文件名（不含扩展名）作为笔记标题的默认显示值。
- 文件夹支持多级嵌套。
- 空文件夹必须显示。
- 默认只将 `.md` 识别为笔记；其他文件作为附件或普通文件处理，不应误显示为笔记。
- 支持中文、英文及常见 Unicode 文件名。

## 5. 主界面与交互设计

### 5.1 三栏布局

从左至右固定为：

1. **目录：** 文件夹分类树。
2. **章节：** 当前文件夹下的笔记列表。
3. **内容：** Markdown 编辑器及预览区。

建议默认尺寸：

| 区域 | 默认宽度 | 说明 |
|---|---:|---|
| 目录 | 220 px | 可拖动调整、可折叠 |
| 章节 | 300 px | 可拖动调整、可折叠 |
| 内容 | 剩余宽度 | 自适应窗口 |

窗口建议最小尺寸为 1000 × 650。记住上次窗口大小、位置、栏宽和折叠状态。

### 5.2 顶部工具栏

建议提供：

- 新建笔记。
- 新建文件夹。
- 搜索。
- 排序选择。
- 编辑/预览切换。
- 保存状态。
- 导出菜单（Markdown、Word、PDF）。
- 主题切换。
- 设置入口。

### 5.3 目录栏

功能：

- 展示根目录和所有子文件夹。
- 展开/折叠目录。
- 新建文件夹。
- 重命名文件夹。
- 删除文件夹。
- 拖拽移动笔记或文件夹（如实现，需防止移动到自身子目录）。
- 右键菜单。
- 刷新目录。
- 点击目录后刷新章节列表。

规则：

- 根目录不可删除、不可重命名。
- 删除非空文件夹前显示影响范围和二次确认。
- 建议删除进入软件回收站，而非立即永久删除。
- 文件夹命名遵守 Windows 文件名规则。
- 文件夹排序可采用名称升序，且保持稳定。

### 5.4 章节栏

展示当前目录下的 Markdown 笔记。

每项至少显示：

- 笔记名称。
- 修改时间。
- 选中状态。

操作：

- 新建、重命名、删除、复制、移动。
- 点击笔记打开内容。
- 右键操作菜单。
- 搜索结果定位。
- 支持按排序规则即时重排。

### 5.5 内容栏

提供编辑模式和预览模式，可选择分屏预览作为增强能力。

编辑能力：

- Markdown 语法高亮。
- 标题 H1-H6。
- 粗体、斜体、删除线。
- 有序列表、无序列表、任务列表。
- 引用块。
- 行内代码和代码块。
- 表格。
- 链接和图片。
- 快捷键。
- 自动保存和手动保存。
- 保存状态提示。
- 切换笔记前检查未保存内容。

建议自动保存采用约 1 秒防抖；保存状态显示“保存中 / 已保存 / 保存失败”。

## 6. 笔记和文件夹管理

### 6.1 笔记 CRUD

| 操作 | 行为 |
|---|---|
| 新增 | 在当前文件夹创建 `.md` 文件 |
| 查询 | 读取文件内容并显示 |
| 修改 | 编辑 Markdown 正文并保存 |
| 删除 | 移入软件回收站或按明确策略删除 |
| 重命名 | 修改文件名，保留 `.md` 扩展名 |
| 移动 | 将文件移动到目标文件夹 |
| 复制 | 生成内容相同的新 Markdown 文件 |

### 6.2 文件夹 CRUD

| 操作 | 行为 |
|---|---|
| 新增 | 在当前目录创建子文件夹 |
| 查询 | 扫描并显示目录结构 |
| 修改 | 重命名文件夹 |
| 删除 | 删除或移入回收站，包含子项时二次确认 |

### 6.3 文件命名与冲突

- 自动补全 `.md` 扩展名，避免重复扩展名。
- 禁止 Windows 不支持的文件名字符及保留设备名。
- 文件名冲突时提示用户修改名称，不得静默覆盖。
- 重命名或移动失败时保留原文件。
- 对文件路径进行规范化，并验证目标路径仍在根目录之内。

## 7. 排序与搜索

### 7.1 排序

默认排序为**修改时间降序（最新修改优先）**。

支持：

- 修改时间降序。
- 修改时间升序。
- 文件名称升序。
- 文件名称降序。

要求：

- 排序作用于当前文件夹。
- 排序切换后立即生效。
- 用户最后一次排序选择持久化。
- 默认使用文件系统 mtime 作为修改时间。
- 同一排序值时使用名称作为稳定次级排序条件。
- 文件保存后更新 mtime，并刷新列表。

### 7.2 搜索

建议 V1.0 提供全局搜索：

- 搜索笔记名称。
- 搜索 Markdown 正文。
- 展示标题、所属目录、修改时间和匹配摘要。
- 点击结果后自动展开目录并打开笔记。
- 搜索不得扫描根目录之外的文件。
- 大型笔记库搜索应采用异步处理，避免阻塞 UI。

## 8. Markdown 附件和图片

建议支持 Markdown 相对路径引用图片：

```text
技术文档/
├── AI架构.md
└── assets/
    ├── architecture.png
    └── workflow.png
```

Markdown 示例：

```markdown
![AI架构](./assets/architecture.png)
```

要求：

- 编辑器和预览能够显示本地图片。
- 插入图片时支持复制到当前笔记目录下的 `assets` 子目录。
- 重命名或移动笔记时，提示并妥善处理相对路径引用。
- 备份时包含被笔记引用的附件；建议默认包含所选目录中的受支持附件。
- 不允许通过恶意 Markdown 或 HTML 内容访问根目录之外的任意本地文件。
- 对 HTML 渲染进行安全过滤，外部链接通过系统浏览器打开。

## 9. 备份与导入恢复

### 9.1 备份范围

支持：

1. 整个笔记库根目录备份。
2. 根目录下任意层级文件夹备份。
3. 空文件夹也应保留在备份结构中。

### 9.2 备份格式

统一使用 ZIP。建议命名：

```text
DataFutureX-Note-Full-20261112-103000.zip
DataFutureX-Note-AI-20261112-103000.zip
```

备份内容：

- 所选范围内的文件夹结构。
- Markdown 文件。
- 图片和附件。
- 必要的文件修改时间等元数据。

不备份：

- 应用缓存。
- 日志。
- 临时编辑文件。
- 与笔记库无关的应用配置。

### 9.3 备份流程

1. 用户选择整库或某个文件夹。
2. 选择 ZIP 保存位置。
3. 扫描并统计文件、目录、大小。
4. 执行打包并显示进度。
5. 校验 ZIP 可读取性。
6. 显示备份成功信息和文件路径。

备份过程中应处理文件正在被编辑或外部修改的情况，尽可能保证备份一致性。

### 9.4 导入流程

1. 用户选择 ZIP 文件。
2. 检查压缩包格式和备份结构。
3. 展示目录、文件数量及总大小。
4. 用户选择导入目标（根目录或指定子目录）。
5. 扫描目标路径冲突。
6. 让用户选择冲突策略。
7. 先解压至临时目录并校验。
8. 确认后再写入目标目录。
9. 刷新目录树和笔记列表。
10. 展示导入结果。

### 9.5 冲突策略

| 冲突 | 可选策略 |
|---|---|
| 目标文件不存在 | 直接导入 |
| 同名文件存在 | 跳过、覆盖、保留两份 |
| 目录已存在 | 合并目录 |
| ZIP 损坏 | 拒绝导入 |
| 不支持的文件 | 按策略跳过并记录 |
| 导入中断 | 保留原有数据，清理或标记临时数据 |

### 9.6 安全要求

- 防止 Zip Slip 路径穿越。
- 解压后所有路径必须位于指定目标目录。
- 限制压缩包大小、解压总大小、文件数量和压缩比，避免 ZIP 炸弹。
- 不自动执行压缩包中的任何内容。
- 覆盖前必须明确确认。
- 导入失败不得破坏已有笔记。
- 记录导入结果和失败文件清单。

## 10. Word 和 PDF 导出

### 10.1 支持格式

- Markdown：`.md`（原始文件）。
- Word：`.docx`。
- PDF：`.pdf`。

导出不得修改原始 Markdown 文件。

### 10.2 导出入口

在内容区工具栏提供“导出”菜单：

- 导出 Markdown。
- 导出 Word。
- 导出 PDF。

默认使用当前笔记名称作为导出文件名，用户可以修改文件名和保存位置。

### 10.3 Word 导出

建议使用 `docx`（docx.js）生成 DOCX。

支持：

- H1-H6 标题。
- 正文段落。
- 粗体、斜体、删除线。
- 有序和无序列表。
- 引用块。
- 行内代码和代码块。
- 表格及边框。
- 超链接。
- 本地图片嵌入。
- 分页和页面边距。

默认版式：

| 属性 | 默认值 |
|---|---|
| 纸张 | A4 |
| 页面方向 | 纵向 |
| 页边距 | 上下左右 2.54 cm |
| 正文字体 | 微软雅黑或宋体，按系统可用字体回退 |
| 正文字号 | 12 pt |
| 一级标题 | 16 pt |
| 二级标题 | 14 pt |
| 三级标题 | 12 pt |
| 图片 | 保持比例，自适应页面宽度 |

中文字体需在目标 Windows 环境中验证。若字体不可用，应使用可用字体回退，不得导致导出失败。

### 10.4 PDF 导出

建议将 Markdown 渲染为独立 HTML，再通过 Electron `webContents.printToPDF()` 输出 PDF。

支持：

- A4 页面。
- 中文字体。
- 标题、段落、列表、表格、代码块和图片。
- 自动分页。
- 页眉、页脚和页码（可配置）。
- 隐藏编辑器工具栏、菜单和应用界面。
- 合理处理长表格和跨页代码块。

PDF 应采用专门的打印 CSS，不直接截取应用主界面。

### 10.5 导出验收

- DOCX 可由 Microsoft Word 正常打开。
- PDF 可由常见 PDF 阅读器正常打开。
- 中文无乱码。
- 表格、代码块、图片排版正确。
- 长文档分页合理。
- 导出文件名和保存位置符合用户选择。
- 导出失败时给出明确原因，不损坏原笔记。

## 11. 主题管理

### 11.1 主题模式

必须支持：

1. **浅色模式（Light）：** 始终使用浅色。
2. **深色模式（Dark）：** 始终使用深色。
3. **跟随系统（System）：** 默认选项，跟随 Windows 当前应用主题。

### 11.2 主题行为

- 默认主题为跟随系统。
- 用户选择后保存到本地配置。
- 重启后恢复上次选择。
- System 模式下监听 Windows 主题变化并立即切换。
- Light / Dark 模式不受系统主题变化影响。
- 编辑器、预览、目录、章节、菜单、弹窗、状态栏均须同步切换。

### 11.3 技术实现

- 使用 CSS Variables 统一定义颜色 Token。
- 分别提供 `light.css` 和 `dark.css`。
- 使用 Pinia 管理主题偏好。
- Electron 主进程通过 `nativeTheme.shouldUseDarkColors` 获取系统主题。
- 通过 `nativeTheme.on('updated')` 监听变化，并通过受控 IPC 通知渲染进程。
- 区分用户偏好 `system/light/dark` 与实际生效主题 `light/dark`。

建议颜色变量包括：

```css
:root {
  --app-bg: ...;
  --panel-bg: ...;
  --editor-bg: ...;
  --text-primary: ...;
  --text-secondary: ...;
  --border-color: ...;
  --selection-bg: ...;
  --accent-color: ...;
}
```

### 11.4 主题验收

- 三种模式均可切换。
- 系统主题改变时 System 模式自动切换。
- 用户固定 Light 或 Dark 时不随系统变化。
- 重启后恢复用户偏好。
- 所有界面元素无明显主题遗漏。
- Markdown 代码高亮在两种主题下均可阅读。

## 13. 安全、可靠性与异常处理

### 13.1 Electron 安全

- `contextIsolation: true`。
- `nodeIntegration: false`。
- 使用 Preload 暴露最小权限 API。
- IPC 参数必须校验类型、长度和路径。
- 禁止渲染进程任意执行文件系统操作。
- 外部链接使用系统浏览器打开。
- 对 Markdown HTML 内容进行安全过滤。
- 不加载不可信远程页面。

### 13.2 文件安全

- 所有笔记路径经过规范化和根目录边界校验。
- 防止 `../`、符号链接等绕过根目录限制。
- 保存采用临时文件写入后替换的安全策略。
- 保存前检查外部修改冲突，避免静默覆盖。
- 文件操作失败时保留原始数据。
- 删除操作提供确认和恢复机制。

### 13.3 异常恢复

- 自动保存失败时提示并保留编辑缓冲。
- 软件异常退出后允许恢复未保存内容。
- 切换笔记前检查未保存状态。
- 文件被外部删除或修改时提示用户。
- ZIP 导入采用临时目录和校验后提交。
- 备份和导入显示进度、成功和失败结果。

## 15. IPC API 设计要求

建议通过 Preload 暴露类型安全的白名单接口，接口仅为设计示例，Codex 实施时需补齐错误码、参数类型和返回类型。

```typescript
interface NoteAPI {
  selectRootDirectory(): Promise<string | null>;
  getFolderTree(): Promise<FolderNode[]>;
  createFolder(parentId: string, name: string): Promise<FolderNode>;
  renameFolder(folderId: string, name: string): Promise<void>;
  deleteFolder(folderId: string): Promise<void>;

  listNotes(folderId: string, sort: SortMode): Promise<Note[]>;
  createNote(folderId: string, name: string): Promise<Note>;
  readNote(noteId: string): Promise<string>;
  saveNote(noteId: string, content: string): Promise<void>;
  renameNote(noteId: string, name: string): Promise<void>;
  deleteNote(noteId: string): Promise<void>;
  moveNote(noteId: string, targetFolderId: string): Promise<void>;
  searchNotes(keyword: string): Promise<Note[]>;

  backupFolder(folderId: string): Promise<BackupResult>;
  backupLibrary(): Promise<BackupResult>;
  inspectBackup(zipPath: string): Promise<BackupManifest>;
  importBackup(zipPath: string, targetFolderId: string): Promise<ImportResult>;

  exportWord(noteId: string, options: ExportOptions): Promise<ExportResult>;
  exportPdf(noteId: string, options: ExportOptions): Promise<ExportResult>;

  getSettings(): Promise<AppSettings>;
  updateSettings(settings: Partial<AppSettings>): Promise<void>;
  getSystemTheme(): Promise<'light' | 'dark'>;
  onSystemThemeChanged(callback: (theme: 'light' | 'dark') => void): () => void;
}
```

要求：

- 前端不得传入任意可执行路径来绕过授权。
- `noteId`、`folderId` 应由主进程管理或映射为受控路径。
- 所有异步接口统一返回明确结果或抛出可识别错误。
- 事件监听必须提供取消订阅方法。
- 不向渲染进程暴露完整 Node.js API。
